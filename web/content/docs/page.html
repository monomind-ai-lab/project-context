03 the session loop

What happens from now on

Installing is not adopting. The record earns its keep through five moments in every working session — and the agents handle all five.

Before substantial work

The agent runs project-context context --task "<one line>" --files <paths> and reads the packet it returns — the owner's constraints, the current state, then the records anchored to the files it named. Reading NOW.md and PLAN.md and searching the registries is the fallback where the CLI is not available. Automatic where the harness discovers the installed skill; the managed block in AGENTS.md / CLAUDE.md covers the rest.

Whenever something surfaces

Anything worth keeping that is not yet a registry entry goes into project-context/inbox/ with project-context capture — one short, dated, attributed note. Deciding what it becomes is deferred to promotion, where it is cheap.

During work

Trigger detection flags moments that produce a durable record — an accepted trade-off, a reproduced bug, a verified benchmark. The agent proposes the entry, and updating the record is what closes the window. When nothing fired, an ack records that honest outcome instead.

At the end

NOW.md is updated to what is now true. Decisions and learnings are appended only if they were earned — durable constraints and verified lessons, not a diary.

When state may be stale

The doctor runs. Read-only, always: it flags stale state, broken links and dead delivery paths, and it never rewrites your judgement.
