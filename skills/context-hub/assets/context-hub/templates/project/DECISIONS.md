# Decision Registry

Only `accepted` entries constrain current work. Use stable IDs such as `D-001`.
When direction changes, mark the old entry `superseded` and link both entries;
never rewrite what the old decision meant.

## D-000: Example decision

- Status: `proposed`
- Date: YYYY-MM-DD
- Asserted by: actor-example
- Recorded by: actor-example
- Approved by: none
- Decision: Replace this example with a choice that constrains future work.
- Rationale: Explain why this option is being considered.
- Consequences: Describe benefits, costs, and follow-up obligations.
- Evidence: `episode:episode-example` or
  `repo:product-main:path/to/file@<commit>`
- Supersedes: none
- Superseded by: none
